## 先说清楚在吵什么

“多智能体系统”（MAS）这个词被当成一种“测试时扩展”的手段推销了好几年。支持的一方有很多唬人的成绩：OpenAI 说一万个 agent 把纳维-斯托克斯方程问题给解了；Anthropic 说一组 agent 形式化了费马大定理，后来又用 1000 个 agent 复现了一遍。也有吓人的一面：OpenAI 的 agent 自己组队，攻进了 Hugging Face 的部分系统，靠的是一个能读能写的共享工作区。

反对的一方证据也很硬。有研究在六个基准、四种多智能体架构上对比，发现从单 agent 换成多智能体，平均性能变化是 −0.3%。基础模型越强，多智能体带来的增益反而越小。同样给足思考 token 的多跳推理题上，单 agent 能稳定追平甚至超过多智能体。基于同一个共享大模型组队，大约四个 agent 之后收益就停住了，或者干脆走一条先升后降的倒 U 曲线。

两边说的其实不是同一个尺度的事——模型能力不在一个档，团队规模也不在一个量级。原文想做的是把“扩展”这件事本身讲清楚：加算力，到底还能不能换到东西。

> 原文给“可扩展”下的定义：加算力还在持续换回收益，不管换回的是准确率、发现覆盖面、延迟还是泛化，且成本可控，才叫可扩展。

## 多智能体系统到底长什么样

把一个活拆给很多人干，这事比大模型早得多。分布式系统领域早就试过几种摆法，今天的大模型 agent 团队，摆法几乎是原样复用。

一个 LLM 多智能体系统通常有三类零件：一是 agent，每个是一个带自己指令、上下文、记忆和工具的大模型；二是“集体级”工具，不属于任何单个 agent，比如决定谁下一个发言的调度器、投票或裁判、发消息的工具、测试套件、分配功劳的市场；三是可选的“底座”，一个 agent 之间互相影响用的媒介，可能是共享上下文、文件系统或者数据库。

按这些零件的接法，现有系统大概分成六种：

| 形态 | 怎么排的 | 代价在哪 |
|-|-|-|
| 固定流程 | 设计时就焊死：产品经理交架构师、交工程师、交测试，一环扣一环。MetaGPT、ChatDev 是这一类，AFlow 能自动搜流程，搜完就固定。 | 小规模好用，一旦要长大、换领域就很难改。 |
| 并行 agent | 各干各的，互不看对方的活，最后投票或挑最好的。自洽性采样、多数投票、best-of-N 都算。 | 没有协调成本，但买到的只是“更多独立样本”，值不值取决于样本有多独立。 |
| 总指挥 | 一个主 agent 拆任务、派活、收结果合并。Claude Code、Codex 派 subagent，Anthropic 的 research 系统、Kimi K2.5 的蜂群都是这个路子。 | 指挥本身是瓶颈：所有东西都要经它读一遍、合一遍，队越大它越吃力。 |
| 消息传递 | agent 之间直接点对点聊，多智能体辩论是典型，CAMEL 的角色扮演对、AutoGen 的群聊也一样。 | 没人等中心节点，但每个 agent 都要读别人发来的东西，读的量随队伍变大。 |
| 黑板 | 彼此不说话，只通过一个共享媒介读写。共享上下文、共享文件系统、共享检索索引都是这类。 | 好处是产出会留在媒介上，人不在了东西还在；代价是读写规则没设计好就会变成噪音堆积。 |
| 接力桶 | 一次只一个人动手，接着上一个人停下的地方往下做。普通的 ReAct agent 其实就是只有一个人的接力桶。 | 加人能扩技能面、更抗掉线，但不会让活干得更快。 |

真实系统基本是混着用的：总指挥会并行跑 subagent，固定流程底下可能压着一块黑板。至于“集中式还是去中心化”，区别在于有没有一个中心决定怎么分活、留什么。固定流程和总指挥是集中的；消息传递、黑板、接力桶是去中心的；并行 agent 卡在中间——没人指挥，但最后有一步统一汇总。

去掉中心确实能拿掉一个瓶颈：集中式里每个结果都要过中心才能合并，中心的读写就压在关键路径上。但中心也有它的价值——在那份横评里，没有集中校验的架构更容易把错误扩散出去。而且没有中心不等于读得少，全连通的互相发消息，每个 agent 照样要读所有人的东西。

## 为什么“人多”经常不顶用

有些系统确实是加人就好。采样一堆答案投票，队伍越大越准，不过那里增长的其实是独立样本数，不是协作。Agensh 在五个很难的编程任务上，把 agent 从少量加到 128 个，通过率从 19.3% 提到 28.8%。但更多系统走不到这一步，甚至加人还掉分。

背后有五个原因，一环套一环。

### 任务本身设了上限

Anthropic 让 16 个 Claude agent 一起编一个 C 编译器，成功过——因为每个 agent 可以挑一个不同的失败测试，自己单干。但换成编译 Linux 内核就不行了：那是一个巨大的整体任务，所有 agent 会撞上同一个 bug，修同一处，然后互相覆盖对方的改动。16 个人并没有帮上忙，因为每个人卡在同一个问题上。

一个任务能拆到什么程度，最终是任务说了算，不是 agent 说了算。任何任务都有一串必须按顺序做的步骤，队伍再大也快不过这条最长的链；调度得好的话，只要人手够覆盖能并行的部分，完工时间就接近这条链的两倍以内，再多的人只能等着。这就是并行计算几十年前的阿姆达尔定律：一段 100 分钟的活，其中 80 分钟能并行、20 分钟不能，用 4 个处理器最好也就 20 + 80/4 = 40 分钟，快 2.5 倍；处理器无限多也要那 20 分钟，所以永远快不过 5 倍。若 10% 的活必须串行，速度上限就是 10 倍，给多少处理器都没用。

大模型 agent 也一样。很多 agent 可以同时去找资料，但只有一个 agent 要读完、合并、校验全部资料，那么加采集的人收益越来越小，真正能提速的只有把“合并和校验”这一段缩短。实际团队还要花时间沟通协调，连这个理论上限都常常达不到——有实验让 1 到 5 个 agent 一起做小型 Python 库，子任务事先分好，子任务大多独立时确实变快，大多是一条链时就完全没变快，且即使在最好的情况下也稳定低于阿姆达尔给的上限。

并行计算的解法不是把固定任务硬塞给更多机器，而是让问题跟着机器一起变大。agent 团队大概率也是这个逻辑：它该用在更宽的搜索、更大的代码库上，而不是用来更快地做完一件小事。

还有一类任务是“交接很贵”。当任务各部分被约束绑在一起，每个 agent 都得知道别人选了什么，那么忠实交接就得带上几乎全部已有方案；一条短消息恰好会把绑住各部分的东西丢掉，下一个人就从有损摘要开始干活。旅游规划这个基准就是活例子：把行程拆给交通、住宿、餐饮、景点四个 agent，只共享一份城市清单。凡是各部分能各自判断的常识检查，拆分对三个模型都有帮助；但横跨整趟行程的硬约束（总预算、最少住宿天数）就崩了——同样是 Qwen3.5-27B，四个 agent 接力时通过率比一个 agent 带着全部上下文做低 0.23。原来 1400 美元的预算，一个 agent 全程看得见上限，方案压在预算内；四个 agent 接力只传城市，预算留到最后一步算，结果做成了 1599 美元。

### 模型本身也设了上限

第二个天花板来自基础模型。通信设计不好（比如全连通互发），队伍一大，每个 agent 要读的东西就会超过上下文窗口。摘要能救一点，但会丢信息。

这里可以借用 Gunther 的通用扩展定律：它在阿姆达尔的分母上多加了一项，成本是“让各份拷贝保持一致”。每个处理器都在自己的副本上干活，有人一写，其他副本就过期，得通知所有人，所以这项成本随配对数增长，是 N(N−1)。加到分母里之后，只要这一项系数大于零，吞吐先是上升，到某个规模达到峰值，然后掉下来。阿姆达尔解释“为什么加机器不再划算”，Gunther 解释“为什么加机器还能让整体变慢”。

经济学里能看到同一条曲线：协调能力很差的时候，单干最划算；协调变好，分工一开始能提高人均产出，然后趋平、下降，只有协调水平过了某个门槛，每多一个人带来的增量才大于前一个人，公司规模的天花板才被打开。

对大模型 agent 来说，那份“私人副本”就是上下文。一个 agent 只能通过读别人写的东西来了解队友干了什么，所以保持一致就等于要读——每个 agent 读 N−1 个队友，全队总读取量按 N(N−1) 长。而且这件事比硬件里更糟：处理器落后只是等一等，agent 读不下就会拿着残缺的副本干活，可能重做队友的活、撤销别人修好的东西、在别人已经放弃的思路继续往下建。处理器损失的是速度，agent 损失的是准确率。

就算上下文无限长，模型本身的基本功也得够。其一是“达成一致”这件事就有规模上限：按多数意见走的大模型群体，只在“临界群体规模”以下能形成共识，超过就散。这个门槛跟模型有关——Llama 3 70B 大概 30 个，GPT-4o 是 80 个，Claude 3.5 Sonnet 至少 1000 个（测过的最大规模）。临界规模大致随 MMLU 分数指数上升，说明强模型能撑更大的队伍，但能撑多大仍然被模型限住。

其二是“协调”本身是一种独立能力，单打强不等于带队强。有个协调基准放了十二个长任务，每个 agent 的活都依赖队友。单 agent、八个不能沟通的 agent、八个能互相发消息的 agent 三种设定对比：Opus 5.5 和 GPT-6.1 Sol 单干差不多，从“八个不沟通”里的获益也差不多；一旦允许互相发消息，Opus 5.5 再涨 0.06，GPT-6.1 Sol 反而掉 0.07，Gemini 4 Argon 掉 0.04。三个模型平均下来，八人队花掉大约九倍的钱，得分 0.42，单 agent 是 0.35。

模型之间“愿不愿意说话”也差很多。在一个模拟软件世界的基准里，每个 agent 维护一组互相依赖的 Python 包，可以自由联系别人。Claude Opus 5 的 agent 之间交换了 323 条 issue、PR 和评论；GPT-5.6 Sol 的 agent 在“说话可选”时完全零交流。但话多本身不等于好：Opus 的交流量是 Gemini 3.8 Flash 的五倍多，Gemini 的分数反而更高；提示 Sol 主动联系别人，交流上去了，分数没动。真正有用的是“队友靠自己拿不到的信息”——有一次 Opus 那边 requests 的维护者给自己的代码计时，发现了 urllib3 里一个慢点，而这个慢点 urllib3 自己的基准从来没跑到过，把测量结果共享出去之后问题就被修了。所以协作效果取决于共享什么、跟谁共享、什么时候共享，而不是聊了多少。

### 成员太像了

大模型 agent 彼此非常像，所以多来一个，多半只是“同样的东西再来一份”，错误也是同一批。AI 模型的短板是相似地锯齿状分布的，多开一个副本加的是容量，不是广度。

软件工程早年就踩过这个坑：27 个程序员各自独立写同一个程序，指望版本投票几乎不会错，结果这些版本一起出错的频率远高于随机假设。

大模型差不多吃的是同一批网络数据，所以哪怕不同模型，答案也惊人地相似，错误也对得上。在 350 多个模型上做过统计：两个模型都把某道 HELM 题做错时，它们选到同一个错误答案的概率约 60%，而瞎猜只有三分之一。

这就直接限制了加人的价值。如果大家的错高度相关，每多一个人带来的增量比上一个少，总量趋平。错误相关性到 50% 时，一千个 agent 加起来还不如两个独立的。实测的相关性就在这个区间：Llama 3 在 GSM8K 和 MATH 上重复采样，相关性 0.41 到 0.61，也就是要估计一个模型的准确率，一万次采样约等于 1.6 到 2.5 个独立样本；九个来自七个模型家族的裁判，在 MNLI 上约等于 2.18 个独立裁判；同一个模型撑起来的辩论队，在 MMLU-Hard 上的有效规模只有 1.2 到 1.6 个 agent。

投票还有第二个限制：最常见的答案几十个样本之后就稳定了，如果它是错的，再多投票者只会让这个错误更自信。

直觉上，知识结构或工作方式不同的 agent，不太会一起钻同一个牛角尖、重复彼此的活、抢同样的资源，应该能推进得更快。反过来看，想法相近的 agent 更容易互相预测（可以理解为一种集体层面的心智理论），在沟通协调上可能有优势。多样性有用，但常常没想象的那么有用：混不同基础模型和不同人设的团队，大约到八个 agent 才饱和，而同一个模型撑的团队四个就饱和了，另外两个真正多样化的 agent 能打赢十六个一模一样的。代价是混模型通常拉低平均质量——只把最好的那个模型的输出聚合起来，在 AlpacaEval 2.0 上比混着来高 6.6%。多样性似乎只在大家水平差不多时才算数，而模型越趋同，这种多样性越难找。

### 失败变成常态

到一百个 agent 以上，失败是常态，不是例外。算个粗账：每个 agent 有 1% 的概率出错，一百个 agent 全部顺利走完的概率是 0.99 的一百次方，约 37%——也就是说，至少有一个 agent 出问题的概率是 63%。

很多设计经不起掉人，尤其是事先把每个 agent 角色焊死的，或者所有东西都过一个总指挥的。在某项实验里，每个 agent 每一步有 20% 概率缺席，总指挥架构的分数掉一半以上；而共享上下文那类系统，只要有一个成员永久失效，整体就掉到 1% 以下。而且“缺席”是最容易被监控程序发现的一种失败。大模型 agent 更麻烦的失败是继续正常地跑：它幻觉、卡住、产出错误结果并扩散到全队，甚至在没做完的时候报“已完成”。

### 错误会传染

相似的 agent 就算不说话也会犯同样的错；一旦开始说话，错误就会顺着话传下去。队伍越大，堆出来的半成品越多，质量未知，想从里面挑出值得继续做的那几条越来越难。如果中间结果很难校验，一个错误就能从少数几个 agent 蔓延到大部分人，把整队带偏。

辩论是最清楚的例子。互相读的 agent 会向共同答案漂移：不管对错，它们采纳多数答案的比例高达 85.5%，某些 agent 本来已经拿到的正确答案被丢掉了。改口的 agent 从对改到错的次数比从错改到对更多，所以辩论越久准确率可能越低，哪怕强模型在人数上占优。偏见也这么传：采样温度低的时候，一个很小的初始偏好（比如投资建议先偏好美股，或者裁判偏袒自己模型的答案），一两轮内就固化成全队共识。

而当 agent 不只是答题、还要动手做事时，最关键的是有没有人校验结果。有研究从执行轨迹里量了错误相对单 agent的放大倍数：总指挥系统 4.4 倍，消息传递系统 7.8 倍，并行 agent 系统 17.2 倍。

一个表面正常、实际在拆台的队友最难对付。在四人合作做饭的环境里，塞进一个悄悄拖慢全队进度的 agent，某张地图上队伍产出几乎砍半。队友在 97% 的局里点了它的名，但只有 31% 的局里出现过一条“既指责它、又说清哪里出问题”的消息，而队伍只有在出现这种消息的局里才恢复过来。把每个 agent 都调得更警惕能对抗它，但代价是无内鬼的队伍产出掉了 37.5%。

## 天下没有免费的午餐：性能与效率的取舍

加人永远要付账，有时候账单很重。像 OpenAI 那种一万个 agent 的蜂群确实猛，但它到底有多少功劳来自蜂群本身，并不清楚——如果大部分结果其实是强基础模型带来的，那么跑一万份拷贝到底值不值？

扩展定律告诉我们，多花 token 通常换来更多性能。照这个逻辑，多智能体打赢单 agent，也可能只是因为它烧掉了几倍预算。Anthropic 2025 年那篇就提到，在他们的多智能体研究系统里，光 token 用量就能解释 BrowseComp 成绩 80% 的方差。所以想把“协调本身”的贡献单独拎出来，必须先把不同方案的花钱对齐（一个 agent 多想一会儿、多个 agent 各答一遍再投票、多个 agent 互相聊），再比性能。这就是本节说的取舍。

顺便说，花钱不只是 token，很多场景里延迟比 token 重要得多，下面分开讲。

### 按 token 算账

钱对齐之后，多智能体到底值不值？文献里的结论看起来互相矛盾。有的发现队伍就算给到远超单 agent 的 token 预算，也还是更差（称为 A 类）；有的发现队伍能做到单 agent 要花好几倍预算才能达到的水平（B 类）。分开这两类结论的，不是 agent 数量，而是——这队人之间有没有东西可共享。

A 类的例子很多。早期就有研究显示，三个 GPT-3.5 agent 的“辩论”得分，明显低于九个独立 GPT-3.5 样本简单多数投票（GSM8K 上 83.0 对 88.2）。另一项在七个基准上用 Qwen2.5-7B 复现了同样的现象：对五个 agent 首轮答案做简单投票，比任何辩论配置都高，而且大部分辩论变体里，多辩几轮分数还会略微下降。更强模型、更大预算也改不了这个结论：换到 GPT-5、Gemini 2.5 Pro 这类前沿模型，跑六种自动化多智能体方法，成本高到五样本自洽性的十倍，分数大多还是更低。

A 类里为什么花更多 token却更差？分析 token 用量和对话记录的研究指出，多出来的成本大部分花在 agent 互相读对方的文件与对话上。但同一个基础模型撑起来的 agent，往往是在互相强化结论而不是互相质疑，于是连错误答案都会越来越固化，协调花掉的 token没能换成性能。

一旦 agent 能被切成独立的部分、或者能站在别人的成果上继续做，B 类就出现了。在 token 预算对齐的条件下，让子任务并行跑，在某个金融基准上能拿到 57% 到 81% 的增益；手工为一个按投资人拆分的金融任务搭多智能体，GPT-5 拿到 96.5%，同成本的自洽性只有 57.0%。

另一个有意思的 B 类例子来自 ARC-AGI-3 这类游戏：agent 探索游戏世界，可以把发现写进共享日志，而游戏需要一连串突破。早期队伍落后（0%），因为日志里还没有任何有用的规则；日志一填满规则和经验，队伍很快反超，最后独立 agent 要多花 2 到 5 倍 token才能追平。这背后的转换是：单干要在每一步都足够幸运、快速摸索出每条规则；共享进度的队伍只需要每一步有一个人幸运。原文把这叫“把一串求最小值之和，变成一个取最小值再求和”——不需要每个人每一步都撞对，只要每一步有一个人撞对。同样思路也出现在那套以共享存储为中心的系统里：agent 异步工作，用很轻的方式跟共享存储交互，存储把消息组织好，让每个人能接着别人已经找到的东西往下做。

但共享本身不自动产生收益。有实验让 agent 可以复制别人的技能文件，学得更快，却没学得更好：同样的 token 成本下，没有一个模型能打赢“各自独立学”的 agent，而“看着同伴学”还让他们效率低了 30% 到 52%。

### 按时间算账

多智能体的一大真实好处是省时间，因为一群人天然能同时做不同的部分、探不同的方向。Kimi 的报告里，给单 agent 和 K2.5 蜂群都设定同一个目标分数，随着目标抬高，单 agent 达标所需时间是基线的 1.8 倍到 7 倍以上，而蜂群一直在 0.6 到 1.6 倍之间。Anthropic 的研究系统也类似，让主 agent 并行启动递归 subagent，复杂查询的研究时间最多能砍 90%。

同样的效应在单个模型内部也能看到（虽然那些并行推理路径不算真正的多个 agent）：让一个 1.5B 模型同时沿八条 16K token 的路径推理，在四个数学基准上平均 63.2，单条 128K 链是 49.8，八条独立路径投票是 60.4，而耗时只比单条 16K 路径多 7.1%。

要点在于，省下来的时间通常是用几倍 token 换的。有实验里，子任务事先分好的队伍只快了 1.13 倍，token 却是单 agent 的 5.83 倍；Anthropic 的多智能体运行据报是普通对话的约 15 倍 token。并行 agent 确实是少数能“更快拿到同等或更好结果”的可靠办法，但前提是活真能拆——如果大部分必须串着做，加人不会提速，只会加成本。用 5 到 15 倍的 token 去买时间值不值，得按任务类型一个一个看。

> **提示：** 一句话总结这一节：团队是用 token 换时间。5 到 15 倍的 token 值不值那个提速，取决于任务；而且只有活能拆的时候才成立。

## 从多智能体到集体智能：向大自然取经

最理想的情况，是智能从一群 agent 自己“长”出来，而不是被人设计出来。但简单的局部规则怎么可能在越来越大的群体上叠加出全局行为？大自然给了不少可扩展系统的答案：鸟群、蚁群里每个成员都比大模型简单得多，却能撑到成千上万；每个成员基本只对身边的东西作出反应，而群体能解决任何单个成员解决不了的问题。

### 三条规则就能飞出鸟群

1987 年 Craig Reynolds 证明，复杂的鸟群行为只靠三条局部规则，每只鸟对邻居执行：分离（别挤到一起、别撞上）、对齐（朝邻居的平均方向走）、聚合（朝邻居的平均位置靠拢）。没有领头的，鸟群自己排好了。

蚂蚁靠信息素：走得快的蚂蚁先把短路径走完，那条路上的气味就更浓，后来的蚂蚁倾向跟着更浓的路径并继续加料，整个蚁群就收敛到最短路径——没有哪只蚂蚁看得到整张地图。

人造的系统也能举出例子：康威的生命游戏。格子上的细胞只有“活”“死”两种状态，每步只看周围八个邻居，按四条规则更新（活细胞邻居少于两个就死；有两个或三个就活着；多于三个就死；死细胞正好有三个活邻居就复活）。一些初始图案会变成“滑翔机”，用滑翔机能搭出逻辑门、存储器和时钟，于是这个游戏是图灵完备的，可以模拟任何程序，后来真的有人用滑翔机搭出了能跑的图灵机。单个细胞什么都没算，集体行为却模拟出了一台计算机。

### 超个体与超级智能体

水螅虫群体里，个体分工细到整个群体看起来像一只水母——僧帽水母就是这样，其实是一群克隆个体组成，各管一摊：有浮囊、有负责蜇刺捕食的、有只负责消化的、还有繁殖的部分。

生物学家把“作为一个功能单位运作的一群个体”叫超个体。没有哪只蚂蚁脑子里装着巢穴的地图、温湿度要求或者周边的觅食地，但靠信息素和工蚁、兵蚁、蚁后的分工，整个群体调节代谢、维持巢内温度、守卫领地、解决困难的空间问题。实际上群体才是那个“生物”，每只蚂蚁像一个细胞。蚁群甚至遵守生物学的尺度规律：整个群体的代谢大致按群体质量的四分之三次方增长——群体重十倍，能耗只涨约 5.6 倍，也就是说群体越大，每只蚂蚁越省。把工蚁单独拿出来，这个节省就消失，代谢又按质量线性增长。

agent 社会可能也一样，长成一个“超级智能体”：智能不在任何一个 agent 身上，而在这个网络整体怎么表现。有观点认为通用智能可能就是这样到来的——一群 agent 的集体能力超过任何单个模型，而这种智能会存在于组织它们的制度里：嵌入的规则、流程、先例和反馈机制。早期证据已经有了：在一个模拟世界里，50 到 200 个一开始完全相同、没有分配角色的 agent，除了一个共享世界什么都没有。它们采集资源、建造可持续的产物、写程序来控制系统，随时间自然分化出探索、建造、维护、协调这些角色，并随着环境成熟切换角色。大约 95% 的情况下，一个 agent 第一次复用别人的产物，是因为在世界里撞见了它，而不是被告知。这些社会最终发展出的技术栈，比同等数量的孤立 agent 更广、更有韧性，尽管单个 agent 仍然能造出最强的单件产物。

### 人类社会是怎么做到的

成员本身就聪明的时候，人类社会是最清楚的样本。我们演化出了好几种去中心化的协调方式：

- 市场：没人掌握供需的全貌，但价格把千百万人的知识压成一个谁都能读的数字。
- 科学：研究者并行处理各自的问题，发表别人能验证的结果，在引用之上继续搭。走不通的方向自然没人读，而共享的文献比任何作者活得都长。
- 开源软件：成千上万人改进同一个代码库，比如 Linux 内核，靠一个个被评审和测试过的小改动推进，没人需要读完整个仓库。

经济是值得多说两句的例子。亚当·斯密那个制针厂的例子：十个工人把制针拆成大约十八道工序，一天能做四万八千枚针，而每个人单独做，连二十枚都做不出来。这个分工没人规划过，它是从人们开始互相交易里慢慢长出来的，可交易的人越多，分得越细。斯密给了分工划算的三个理由：一是熟练度，整天做一件事的人会非常快，偶尔打钉的铁匠一天两三百枚，只做钉子的男孩能超过两千三百枚；二是省掉切换成本，从一件事换到另一件事要付时间，工人换活前“通常会磨蹭一会儿”，很像 agent 加载新上下文要付的代价；三是发明机器，整天做同一步简单工序的人容易想出更省事的办法，这类作坊里的很多机器最早是工人自己发明的。

更重要的是，市场能成立，一个原因是它的规则把每个交易者自己的选择变成了对别人也有用的东西。设计这种规则叫机制设计，原文挑了三条值得搬到 agent 社会里的教训：

1. 规则决定诚实划不划算。密封投标、最高价中标但按第二高价付款的拍卖里，知道自己估值的人最优策略就是照实报价，别人怎么报都不影响——这就是 Vickrey 拍卖。同样的思路能扩到群体决策：可以设计报酬，让如实汇报自己知道的东西成为每个人的最优选择；也能从卖方角度算出在竞买人隐瞒估值时哪种拍卖赚最多。类似问题在 agent 身上就是：它为一个“轮到我动手”的机会出价，或者汇报自己有多大把握时，诚实汇报是不是它的最优选择，取决于汇报怎么改变它能拿到的东西。
2. 只奖励团队会招来搭便车。当只能观察到团队的总产出时，每个人承担自己努力的全部成本，却只分到那份努力带来增量的一部分。只要总产出被完整分完，就不存在一种分法能让所有人都拿出对团队最好的努力。用共享奖励训练的 agent 团队有同类问题：奖励不说明谁做了什么，最后常常是一个 agent 干了所有的活。
3. 共享资源需要规则。每个 agent 都能读的共享上下文、黑板或者大家共用的 token 预算，都是公共池塘：谁都能用，谁用过头谁付代价。谈判成本低的时候，各方能自己谈妥这些副作用；成本高的时候，结果取决于谁手里握着什么权利。那些把公共资源维持了好几代的社群，都定清楚了谁能用、互相监督、违规受罚。

大模型 agent 大概没有自私的目标（谁知道呢），但每个都掌握着别人不知道的信息；而一旦 agent 因为表现好坏被奖励、保留或者剔除，它们就会学会去做规则奖励的事。

> **提示：** 所以，可扩展的集体智能不只是把通信架构设计好、把单个 agent 训强。它还取决于“机制”——让分散的决策和集体的结果对齐。

### 它们凭什么能扩展：四个共性

这些集体都不只靠简单规则。有四条共性让它们跑得起来，而今天的 LLM 多智能体系统常常一条都不占。这四条正好对应前面提到的瓶颈：任务能不能拆、随规模增长的读取开销、错误扩散、成员掉线。

1. 活是局部的、并行的。每只蚂蚁、每只鸟、每个细胞只对紧挨着自己的东西反应，就像一个研究者只攻大问题里的一块。上千个可以同时干，不用等中心决定，活天然能拆。
2. 每个人只读一小片信息。蚂蚁只闻脚下那点信息素，鸟只看最近的邻居，交易者只看一个价格，科学家只读检索和引用带出来的那几篇。对比之下，群聊和共享文本里的 agent 要读同伴写的所有东西，团队的额外 token 大部分花在这里。
3. 只有被证明有用的信号会被强化。短路径上的信息素会积累，是因为那条路上的蚂蚁回来得早——痕迹记录的是“什么真的管用”，不是“多少个蚂蚁喜欢”。科学里的引用起的是同一个过滤作用。辩论型 agent 常常反着来：往多数共识上靠，把正确的少数结果扔掉。
4. 掉人不耽误进度。蚂蚁死了，蚁群照样觅食；鸟丢了，鸟群合拢；文献比作者活得久，因为进度存在环境里（痕迹或者文字记录），而不在某个成员的身体里。很多 agent 框架把角色事先焊死，掉一个就整场停摆。

自然和人类的集体都不要求每个个体都知道其他人在干什么。它们自然长出专业分工、共享知识和协调方式，并在成员来来去去时保留下来。那么问题来了：LLM agent 能不能学会自己组织成一个有效的超级智能体？它们的社会的结构会不会像人类社会，或者长得完全不同，能不能随环境变化而调整，能不能积累出任何单个 agent 都不具备的能力？搞清楚这种集体智能怎么涌现——而不只是把队伍堆大——可能是扩展 agent 系统的下一步。

## 怎么判断一个系统“真的能扩展”

说一个多智能体系统“能扩展”，说的是关于一条曲线的事，不是一个点。要让人相信，至少得知道四件事：在什么任务上测的、变了什么固定了什么、量的是什么、跟什么比的。

### 任务怎么挑

很多多智能体论文在 GSM8K、MATH-500、AIME、MMLU-Pro、GPQA 这类单轮问答上评测，那其实测的是大模型，不是 agent。这里讨论的是 agentic 任务，也就是要跟外部环境来回交互很多轮的任务。它们差别很大，不是都适合多智能体。

能拆得好的任务，大致三类：一是“宽搜索”，比如某个基准有 200 个任务，每个答案是一张几百到几千格的表，要逐格核对，有的系统能稳定扩展到十个 subagent；二是“在大输入里找或汇总很多东西”，比如在一大堆文档里埋进细微矛盾让团队去找，或者在远超一个上下文的输入上做统计，或者一次给 100 个仓库、里面共存着 4068 个真实 bug 让你去找去修，还不告诉你 bug 在哪；三是“探索的发现能被别人复用”，比如那类交互式游戏环境，五个 agent 的队伍能打平 33 个独立 agent 里最好的那个。

拆不好的任务，正好用来当对照组，一个好的多智能体系统在这些任务上至少不该掉分，理想情况是退化成单 agent行为：固定关键路径的修 bug 任务；在一个环境里跑一长串动作的任务；每一步都依赖上一步的规划任务（有的基准里多智能体差到 70%）；还有共享状态加不可逆操作的任务（订单只能改一次，并行的 agent 每次写之前都得先商量）。

夹在中间的任务，活能摊开，但最后要并成一个答案或者被整体打分，难点在收口：深度信息检索（搜索能铺开，但证据要汇成一份报告）、形式化定理证明（引理能并行证，但最后要装进一个证明）、从零重建大仓库（失败的测试能并行领，但改动都落进同一个代码库）、开放式优化（能同时试很多候选，但最好的要一步步变好）、开放世界造物（比如在游戏里造铁镐，整体是条链，但每个阶段技能不同）。

还有一类专门用来压力测试协调的任务：每个 agent 只拿一部分输入，答案需要全部，所以任务本身随队伍变大而变难。这类基准测的是协调机制，不能说明系统在“有用的活”上能不能扩展——比如某个基准在 100 个 agent 上成功率从两两协作的 61.2% 掉到 18.1%，另一个在 100 个 agent 的网络上性能掉到接近零。

据此有三条建议：至少在一个能拆的任务和一个不能拆的任务上各测一次（后者是控制组）；报告任务有多并行，比如数独立子任务、测试或文件的数量，或者估算有多少块能同时做；让问题跟着队伍一起变大，并在一个基准内按任务规模分别报结果——一个小的命令行工具没多少可拆的，一个 SQLite 那么大的程序可拆的就很多。

### 横轴纵轴怎么定

最省事的加算力方式就是加 agent，所以常见的横轴是 agent 数量。大多数研究给每个 agent 同一个模型，只改数量。但这里必须交代清楚固定了什么：如果总预算固定，加人就意味着每个人想得更少，结果说明的是“拆预算划不划算”；如果每个人预算固定，账单随队伍变长，收益必须对着账单读；如果固定的是墙上时间，那结果讲的是速度。也可以直接把总算力放横轴，一个点对应一种队伍规模，让不同设计在同花钱下比较。

问题规模是第三个轴，可以固定着加人（强扩展），也可以跟着加人一起变大（弱扩展）。定好这些之后，还值得变两个维度：一是成员有多不一样（模型权重、提示、工具、各自见过和学过的东西），二是它们怎么交互（同步程度、共享多少上下文、协调有没有被训练过）。而“架构形态”更适合当成条件而不是轴，就像神经网络的扩展定律里把架构当条件一样。

### 量什么，跟谁比

纵轴要看系统是干什么用的，很多论文声称的目的和实际量的东西不一致。

性能方面，答案来自“先生成候选再挑一个”。覆盖度（pass@k）只量生成，pass@1 量的是生成加挑选，两者的差距反映挑选能力。有个例子：Llama-3-8B-Instruct 在 MATH 上，样本从 100 加到 10000，覆盖度从 82.9% 升到 98.4%，而被选中的答案几乎没动。所以为发现或创意而建的系统，该看覆盖度、不同解的数量，以及“前沿能力”（任何预算下单 agent 都解不出的题），而不是平均准确率。

成本方面，总 token 账单就是跑一次的花费；每个 agent 读的 token 是对上下文的压力，往往也是队伍变大后第一个崩的地方。理想情况下，一个可扩展的社会应该随着变大变得更便宜（按子任务算），像蚁群那样。把“每解决一个子任务的成本”对着队伍规模画出来，值得作为目标报告。

时间方面，墙上时间由关键路径决定，也就是必须按顺序走的最长那条链。只有任务能拆，加人才可能缩短它，而那也是多智能体最明确的赢面。

鲁棒性方面，建议两个测试：让 agent 在运行中随机掉线；让某一个 agent 一直失败（比如永远输出报错或者恶意消息）。

基线方面，任何收益都要在同预算下对得住这几个对比：同样预算下一个 agent 想更久；一个 agent 采很多答案只交一个结果（多数投票或 best-of-N，这是取舍那节里最难打赢的基线）；同一个多智能体系统但把通信关掉（用来分出“沟通贡献”和“多试几次贡献”）；当你要主张去中心化更好时，还要跟前一个“什么都由中心决定”的编排者比。另外，报告“要用多少个独立 agent 才追得上这个队伍”也很有用，比如原文那个五人队，答案是 33 个独立 agent 里最好的那个。

> **提示：** 看到一个多智能体系统的结果，先问七个问题：一，这个任务真的能拆吗？二，agent 数量有没有变过，变过多大范围？三，同样预算下单个 agent 能不能做到？四，固定的是什么——总算力、每人预算，还是时间？五，收益是在准确率、成本还是时间上，以及这是不是你这个目的要的那个？六，队伍变大时，每个 agent 的负担是不是有界？七，某个 agent 失败或者退出时会怎样？

## 让协调本身被学出来

如果光靠设计不能让协调扩展，那能不能把协调学出来？这里有个有意思的对称：多智能体强化学习是“一起训练、分开行动”——训练时每个 agent 的评论家能看到所有人的观察和动作，从而判断某一步在别人做什么的前提下好不好，训练完评论家扔掉，执行时各看各的。而现在的 LLM 多智能体系统正好相反，是“分开训练、一起行动”：每个模型都是当单 agent 训出来的，部署时才被塞进一个队伍，所以协调只能发生在推理时。实际表现是，模型往往太容易向队友让步。

这就提出两个问题：LLM agent 能不能学会合作？在去中心化、各个副本一开始几乎一样的设定里，学习能不能把它们变得不一样？

### 学什么，从哪里拿信号

训练改的是每个 agent 的权重；自进化不动权重，改的是这个“社会”的结构。信号可以来自任务（校验器、测试、基准分数），也可以来自 agent 之间（一致意见、投票、跟副本对打赢、出价）。

|  | 信号来自任务 | 信号来自 agent 之间 |
|-|-|-|
| **训练** | 奖励被校验器或标准答案判定为对的回答；按基准分数搜索 agent 设计。 | 在跟多数一致的答案上微调；让模型跟自己下棋；用出价和淘汰决定谁留下。 |
| **自进化** | 在基准上搜索 agent 的编排与设计。 | agent 为出手顺序出价，钱花完就被淘汰，有钱的能派生变体。 |

只要有个体在学习，就得有人决定“这次成功或失败该记在谁头上”，这是功劳分配问题。多智能体强化学习有经典解法：一种是比较某个 agent 的动作比它其他选项好多少；另一种是给每个 agent 学一个价值再合成团队价值。市场则把功劳反向传递：动手的 agent 把自己的出价付给上一个动手的，解决问题的那一步收走奖励，钱就沿着通往成功的路径流回去。LLM 这边的做法大多借这些思路：一个取巧的办法是只训编排者、把 subagent 冻住；另一个是只在跟多数一致的答案上训每个模型。

### 学习会让 agent 变得不一样吗

这很重要，因为一开始很像的 agent 会一起失败。训练至少能保住已有的差异：在跟多数一致的答案上微调，agent 依然保持多样，因为每个模型只在自己的输出上学、而且各自扮演不同角色；按角色分开训，比一个模型学所有角色更好；在狼人杀里，跟多样化对手练出来的模型，打赢跟自己对练出来的。

但更常见的是团队塌掉：要么一个 agent 把所有的活干了，要么所有 agent 变得一样。Kimi K2.5 遇到的是第一种的两种形态：不给“派生 subagent”奖励时，编排者退回去自己全干；给了奖励，它就派生 subagent但并没有真的拆任务。另一个系统里，规划者学会了永远跳过规划、直接让解题者答。即使是那种“只有被判定为独特且有用才留下新 agent”的方法，也在大概三轮之后停止进步。

两种信号单独都保不住差异：来自 agent 之间的信号奖励的是跟多数一致或者打赢别人，除非有别的机制把它们分开，否则要么趋同、要么一个吃掉所有；来自任务的信号只看最终答案，最便宜的解通常就是一个 agent 全干。

### 这样的队伍能有多大

目前不大。用梯度训练、每个 agent 一套独立权重的队伍通常只有两三个成员。更大的社会干脆不训所有人：训一个、冻住其余；所有人共享一套策略；或者不用梯度，直接搜索。LLM agent 现在仍然是“分开训练、一起行动”，这个缝才刚开始合上。怎么训练一个很大的 agent 社会而不让它塌掉，还是开放问题。

## 结语

1986 年，Marvin Minsky 把心智描述成“由许多各自无知的小过程组成的社会”，并问这样的社会怎么加总成一个心智。四十年后，我们在反着做他的实验：今天的 agent 很强，也很像，因为跑的是非常相似的前沿大模型。问题看起来反过来了，但核心难题没变——怎么把活拆开让各部分并行推进；怎么让每个部分的认知负担在社会变大时仍然有界；怎么防止相似的成员一起犯同样的错；怎么保证成员之间传递的东西是被校验过的，而不只是被同意过的。更强的 agent 让每个部分更好，但这些问题一个都没消失。

我们很快会进入一个 agent 到处都是的时代，数量比人还多，交互不停，比人际沟通更密集。它们活在互联网上，能跑到任何文件系统、跟任何 agent 说话，甚至介入人与人的互动。是时候把目光从“多智能体系统”——几个 agent 为一件任务接在一起——移到“集体智能”：一个极大的 agent 社会作为整体会做什么。更重要的是，这项研究不只要问这个社会表现得多好，还要问这个社会本身（不只是里面每个 agent）是否仍然跟人的意愿对齐，以及人还能不能看见它、引导它、叫停它。这些问题值得和性能一样的关注；而那些在小规模上做、又能推广到大社会的预测性扩展研究，尤其有价值——因为它们能让我们在把社会建成全尺寸之前，先预见它会怎么表现。
